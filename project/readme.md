# Финансовый Микросервис (Gateway & Ledger)

Проект представляет собой модульное приложение на Go, разделенное на два ключевых сервиса: **API Gateway** (HTTP-сервер) и **Ledger** (сервис учета транзакций с собственным хранилищем в памяти).

## 📁 Структура проекта

```text
project/
├── README.md
│
├── api-gateway/                  # HTTP API Gateway
│   ├── go.mod                    # Зависимость от модуля ledger
│   ├── main.go                   # Точка входа, запуск сервера
│   ├── server.go                 # Сервер и зависимости
│   ├── router.go                 # Регистрация HTTP-маршрутов
│   ├── handlers.go               # Обработчики запросов
│   ├── response.go               # Формирование JSON-ответов
│   └── middleware.go             # Логирование HTTP-запросов
│
└── ledger/                  # Сервис учёта (финансовая логика)
    ├── go.mod
    ├── main.go              # Точка входа для Ledger
    ├── budgets.json         # Бюджеты в формате JSON
    ├── models/
    │   ├── transaction.go   # Структура Transaction
    │   └── budget.go        # Структура Budget
    └── repository/
        └── memory.go        # Хранилище Storage в памяти
```

## 🚀 Как запустить и проверить сервисы

### 1. Запуск API Gateway (HTTP-сервер)
Перейдите в папку шлюза и запустите сервер:
```bash
cd api-gateway
go run main.go
```
* **Проверка работы:** Откройте браузер по адресу [http://localhost:8080/ping](http://localhost:8080/ping). Вы должны увидеть ответ `pong` со статусом `200 OK`.
* **Остановка сервера:** Нажмите `Ctrl + C` в терминале.

# API Gateway

HTTP-шлюз для работы с транзакциями и бюджетами. Gateway использует модуль `ledger` для бизнес-логики и хранения данных в памяти.

## Запуск проекта

Перейдите в директорию Gateway:

```bash
cd api-gateway
```

Запустите сервер:

```bash
go run .
```

По умолчанию сервер доступен по адресу:

`http://localhost:8080`

Данные хранятся в оперативной памяти и сбрасываются при перезапуске приложения.

## Эндпоинты

| Метод | Эндпоинт | Описание | Успешный статус |
|---|---|---|---|
| `GET` | `/ping` | Проверка доступности сервера | `200 OK` |
| `POST` | `/api/transactions` | Создание транзакции | `201 Created` |
| `GET` | `/api/transactions` | Получение списка транзакций | `200 OK` |
| `POST` | `/api/budgets` | Создание бюджета | `201 Created` |
| `GET` | `/api/budgets` | Получение списка бюджетов | `200 OK` |

## Примеры запросов

### 1. Проверка доступности сервера

```bash
curl -i http://localhost:8080/ping
```

### 2. Создание транзакции

```bash
curl -i -X POST http://localhost:8080/api/transactions \
  -H "Content-Type: application/json" \
  -d '{
    "amount": 450,
    "category": "еда",
    "description": "ланч",
    "date": "2025-09-10"
  }'
```

Ожидаемый статус: `201 Created`.

### 3. Получение списка транзакций

```bash
curl -i http://localhost:8080/api/transactions
```

Ожидаемый статус: `200 OK`.

Если транзакций нет, API возвращает пустой массив:

```json
[]
```

### 4. Создание бюджета

```bash
curl -i -X POST http://localhost:8080/api/budgets \
  -H "Content-Type: application/json" \
  -d '{
    "category": "еда",
    "limit": 5000,
    "from": "2026-10-01T00:00:00Z",
    "to": "2026-10-31T23:59:59Z"
  }'
```

Ожидаемый статус: `201 Created`.

Поля JSON должны соответствовать структуре `CreateBudgetRequest` в проекте.

### 5. Получение списка бюджетов

```bash
curl -i http://localhost:8080/api/budgets
```

Ожидаемый статус: `200 OK`.

Если бюджетов нет, API возвращает пустой массив:

```json
[]
```

## Обработка ошибок

Все JSON-ответы используют заголовок:

`Content-Type: application/json; charset=utf-8`

Ошибки возвращаются в едином формате:

```json
{
  "error": "описание ошибки"
}
```

| HTTP-статус | Значение |
|---|---|
| `400 Bad Request` | Некорректный JSON или ошибка валидации |
| `405 Method Not Allowed` | HTTP-метод не поддерживается |
| `409 Conflict` | Превышен бюджет |
| `500 Internal Server Error` | Внутренняя ошибка сервера |

## Логирование запросов

Middleware логирует для каждого HTTP-запроса:

- HTTP-метод;
- путь;
- длительность обработки.

Пример записи в консоли:

```text
POST /api/transactions duration=1.234ms
GET /api/budgets duration=0.876ms
```

## Технологии

- Go
- `net/http`
- Модуль `ledger`
- Хранение данных в памяти
- JSON API
- HTTP middleware для логирования


### 2. Запуск Ledger Service (Логика и Репозиторий)
Откройте соседний терминал, перейдите в папку ledger и запустите его:

## 🧪 Тест-кейсы в `runBudgetScenario()`

В хранилище по умолчанию уже существуют бюджеты для категорий **«еда»** и **«транспорт»**.

Проверяются следующие сценарии:

1. **Обновление бюджета «еда»** — через `SetBudget()` добавляется бюджет «еда» на 1–31 октября с лимитом 5000. Проверяется отсутствие дубликата при совпадении периода.
2. **Загрузка из JSON** — дополнительные бюджеты загружаются из файла `budgets.json`.
3. **Транзакция 3000** — успешно добавляется в октябре и не превышает лимит.
4. **Транзакция 2500** — отклоняется, так как превышает общий бюджет категории «еда».
5. **Транзакция 2000 в ноябре** — успешно добавляется, так как находится вне периода октябрьского бюджета.
6. **Транзакция 4000 «развлечения»** — успешно добавляется для категории без бюджета.
7. **Проверка результата** — выводятся список бюджетов через `ListBudgets()` и список сохранённых транзакций через `ListTransactions()`.
